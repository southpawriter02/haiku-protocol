## Objective

Curate three representative procedural documents (Simple, Medium, Complex) from publicly available sources that will serve as standardized test cases for compression benchmarking. Ensure diversity across tool domains and verify token counts fall within expected ranges before advancing to baseline metrics collection.

---

## Selection Criteria Framework

Procedural documents form the optimal test set for the Haiku Protocol because they contain dense, conditional instructions amenable to CNL transformation. Use the following criteria to evaluate candidates:

**Document Style Requirements:**
- Must be procedural/how-to format (step-by-step instructions, command sequences, workflows)
- Should contain warnings, prerequisites, or branching logic
- Avoid narrative, marketing, or theoretical content
- Prefer technical documentation over conceptual guides

**Source Recommendations:**
- Man pages: `git commit --help`, `docker run --help`, `kubectl apply --help`
- Official documentation: Kubernetes guides, Docker tutorials, AWS CLI help pages
- README.md files from mature open-source projects (50-200+ stars)
- Stack Overflow accepted answers (procedural type, 500+ upvotes)
- Technical blog posts on setup/configuration procedures
- API endpoint documentation (request/response format specifications)

**Diversity Requirements:**
- Each document must come from a different tool/domain
- Suggested domains: version control (Git), containerization (Docker), orchestration (Kubernetes), cloud CLI (AWS), package management (npm/pip)
- Aim for variety in procedural complexity and prerequisite chains

## Complexity Classification Rubric

Use this rubric to determine whether a candidate document fits Simple, Medium, or Complex:

```
┌─────────────────────────────────────────────────────────────┐
│ SIMPLE (50–100 tokens)                                      │
├─────────────────────────────────────────────────────────────┤
│ • Single clear procedure, no branching                       │
│ • 1–3 sequential steps                                       │
│ • 0–1 prerequisites (optional: basic knowledge assumed)      │
│ • No warnings or conditional logic                           │
│ • Examples: Basic command usage, simple deploy steps         │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ MEDIUM (200–500 tokens)                                     │
├─────────────────────────────────────────────────────────────┤
│ • Multi-step procedure with some conditional branches        │
│ • 4–8 logical steps                                          │
│ • 2–3 explicit prerequisites or dependencies                 │
│ • 1–3 warning/note blocks or decision points                 │
│ • Examples: Setup with error handling, config with options   │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ COMPLEX (1000+ tokens)                                      │
├─────────────────────────────────────────────────────────────┤
│ • Full tutorial or multi-section guide                       │
│ • 8+ steps across multiple subsections                       │
│ • 3+ nested prerequisites or conditional paths               │
│ • Multiple warning blocks, troubleshooting sections           │
│ • Cross-references to other procedures                       │
│ • Examples: Full deployment guide, cluster setup procedure   │
└─────────────────────────────────────────────────────────────┘
```

    },

    "notes": "",

**Verification Steps:**
1. Save raw text to temporary file
2. Count lines and rough token estimate (4 chars ≈ 1 token rule of thumb)
3. Skim for procedural markers: "Step", "Configure", "Install", "Deploy", "Run", "Execute"
4. Confirm no proprietary headers, copyright restrictions, or paywalls
5. Check for formatting artifacts (broken HTML, mojibake, excessive markdown artifacts)
6. Verify diversity: no two samples from same tool/company

## Python Script: Automated Complexity Scoring

Use this script to assist in document selection and verify preliminary complexity:

```python
#!/usr/bin/env python3
"""
Automated Complexity Scoring for Document Selection
Score documents on procedural density and structural indicators.
"""

import re
from pathlib import Path
from typing import Dict, Tuple

def score_document_complexity(text: str) -> Tuple[float, Dict[str, int]]:
    """
    Score document complexity (0.0–1.0) based on procedural markers.
    Returns (score, indicators_dict).
    """
    indicators = {
        "step_markers": len(re.findall(r'\b(?:step|part|section)\s+\d+', text, re.I)),
        "command_blocks": len(re.findall(r'`[^`]+`|code block', text, re.I)),
        "warnings": len(re.findall(r'\b(?:warning|caution|note|important)\b', text, re.I)),
        "conditionals": len(re.findall(r'\b(?:if|else|when|unless|depending)\b', text, re.I)),
        "prerequisites": len(re.findall(r'\b(?:prerequisite|require|before|first)\b', text, re.I)),
        "cross_references": len(re.findall(r'(?:see also|refer|link to|read)', text, re.I)),
    }

    # Weighted scoring
    score = (
        (indicators["step_markers"] * 0.2) +
        (indicators["command_blocks"] * 0.15) +
        (indicators["warnings"] * 0.15) +
        (indicators["conditionals"] * 0.2) +
        (indicators["prerequisites"] * 0.15) +
        (indicators["cross_references"] * 0.15)
    )

    # Normalize to 0.0–1.0
    score = min(score / 10.0, 1.0)
    return score, indicators

def classify_by_score(score: float) -> str:
    """Classify complexity tier by score."""
    if score < 0.35:
        return "SIMPLE"
    elif score < 0.70:
        return "MEDIUM"
    else:
        return "COMPLEX"

if __name__ == "__main__":
    # Example usage
    sample_text = """
    Step 1: Install Docker.
    Step 2: Configure your environment.
    Step 3: If using Linux, adjust permissions.
    Prerequisites: Administrator access, 2GB RAM.
    Note: This requires elevated privileges.
    """

    score, indicators = score_document_complexity(sample_text)
    tier = classify_by_score(score)
    print(f"Complexity Score: {score:.2f} → {tier}")
    print(f"Indicators: {indicators}")
```

## Decision Tree: Document Selection

Use this decision tree when evaluating potential documents:

```
START: Candidate document identified
  │
  ├─► Is it procedural (step-by-step instructions)?
  │   ├─ NO  → REJECT (need procedural content)
  │   └─ YES → Continue
  │
  ├─► Is it publicly available (no paywall/proprietary)?
  │   ├─ NO  → REJECT (policy: public sources only)
  │   └─ YES → Continue
  │
  ├─► Estimate token count (rough 4-char ≈ 1-token rule)
  │   ├─ Outside all ranges? → CONSIDER EDITING or REJECT
  │   └─ Fits one tier? → Continue
  │
  ├─► Is domain different from existing samples?
  │   ├─ NO  → CONSIDER ALTERNATIVE SOURCE
  │   └─ YES → Continue
  │
  ├─► Save document to benchmarks/samples/[tier].md
  │   │
  │   └─► Run automated complexity scorer for validation
  │       └─► Does score match expected tier?
  │           ├─ NO  → Reconsider classification
  │           └─ YES → Document finalized, proceed to v0.0.3b
```

## Handling Out-of-Range Documents

**If a promising document falls outside token ranges:**
- For Simple-tier: If 101–150 tokens, accept with note (minor extension)
- For Medium-tier: If 150–200 tokens, trim non-essential sections; if 500–700 tokens, excerpt longest subsection
- For Complex-tier: If >1500 tokens, excerpt most representative sections (setup + troubleshooting); if <800 tokens, consider Medium-tier instead
- Document any edits in a `EDIT_LOG.txt` file in `benchmarks/samples/`

## Limitations & Constraints

- **Public Sources Only:** Documents must be from publicly accessible sources (official documentation, GitHub repos, Stack Overflow). Proprietary internal docs are excluded.
- **English Only:** This version targets English procedural documentation. Multilingual complexity is out of scope.
- **Text-Only:** Avoid documents with heavy reliance on images, diagrams, or embedded media (difficult to tokenize accurately).
- **License Compatibility:** Verify source licenses are compatible with the Haiku Protocol project license (typically MIT/Apache-2.0).

## Troubleshooting

**Issue:** Difficulty finding documents that fit complexity ranges.
**Solution:** Expand search to technical blog posts and tutorial sites; use web search terms like "step-by-step guide to [tool]" or "[tool] installation procedure".

**Issue:** Selected document has token count significantly off.
**Solution:** Check for embedded code blocks, tables, or command listings that inflate size; consider extracting a representative excerpt instead of using the full document.

**Issue:** Same tool/domain represented in multiple samples.
**Solution:** Deliberately select from different categories (version control, containerization, orchestration, cloud CLI, package management).
